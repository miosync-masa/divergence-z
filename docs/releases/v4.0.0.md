# Divergence-Z v4.0.0 — Character Bible → Translation & Voice

**From line-level Z-axis estimation to a character bible built from the source text.**

v4 rebuilds Divergence-Z around one idea: before translating or voicing a character, build the
reference material a human translator or scriptwriter would prepare — who the characters are, how the
text refers to them, and what each of them has lived through — and give that material to the model.

```
source text ─┬─ CAST     who is who, and every way the text refers to them
             ├─ PERSONA  who the character is (voice, core identity, conflicts)
             ├─ EPISODE  what the character lived through (quotes verified against the source)
             │
             ├─▶ TRANSLATE  chapter by chapter, with the bible, a running glossary and prior chapters
             └─▶ VOICE / CHAT  new, non-canonical lines in the character's own voice
```

## Why the change

v3 estimated a Z-axis state per line (z / z_mode / z_leak), translated, and scored the result with
IAP / ZAP. Both the per-line estimates and the preservation scores relied on heuristics that could not
be validated. v4 drops per-line estimation and scoring: the model reads the whole chapter with the
character bible in context, and only checks that can be verified deterministically remain
(paragraph alignment, missing dialogue, quote verification). The v3 pipeline is kept in
`divergence_z/old/` so the results in `Result/` stay reproducible.

## What's new

**Building the bible**
- **Cast extractor** — lists every character and every expression used for them ("she", "the passenger",
  "the girl who came from space"…), with disambiguation notes, so lines can be attributed in works that
  never name their characters.
- **Persona / episode extraction from source text** (txt, md, PDF, EPUB; folders read in natural order).
  Quotes in personas and episodes are verified against the source, including dialogue split by
  narration (「…」と彼は云った。「…」).
- **Web generation** (`persona_generator.py` → `episode_generator.py`) for characters without source text.

**Using the bible**
- **Chapter translator** — long chapters are first planned by the model into scene-level sections, then
  translated one section per call. Each call receives only the cast entries, personas and episodes of the
  characters in that section; episodes are split into "already happened / this chapter / not yet"
  relative to the chapter. A glossary of term and voice decisions is carried across chapters. Runs resume
  section by section.
- **Excerpt comparison** — translate a paragraph range under `full` / `cast` / `none` context and get a
  side-by-side file, to inspect what the bible changes.
- **AI chat** — talk with a character; the system prompt is a user-editable template with the persona and
  episode YAML inserted in full. Logs stay on the local machine.

**Desktop app (BYOK)**
- Electron app with a bundled local engine — no Python or Node needed. API keys are stored in the OS
  keychain and never reach the UI layer; the engine listens on 127.0.0.1 only.
- Pipeline with review gate, cost/context estimate before running, cast editor, bitext viewer, glossary,
  voice, web generation, AI chat, per-step model selection.
- Builds for macOS (Apple silicon, Intel) and Windows.

**Under the hood**
- One LLM layer for OpenAI (Responses API) and Anthropic (Messages API): model registry with context
  window / effort levels / pricing, prompt caching, cancellation mid-request, error classification.
- Default models: `gpt-5.6-sol` for extraction and translation, `claude-opus-5-5` for voice and web
  generation. Claude Opus 4.8 is also registered.

## Observations so far

Small, qualitative comparisons — not a benchmark.

- **A work the model does not know** (*STARGAZER*, episode 14, English, full bible vs. no context):
  208 of 371 paragraphs were identical; the differences concentrated in short dialogue. With the bible,
  the translation kept a pun from an earlier chapter (「ほったいもいじるな」 → *"What tater is it?"*), avoided
  a circular definition in the scene where a character learns what "try" means (*"give it a go"*), kept
  nameless characters' designations consistent, and preserved a call-and-response pattern. Without it,
  the model filled gaps with invented characterization.
- **A work the model knows well** (*A Christmas Carol*, Morita Sōhei's Japanese translation → French):
  differences were small; without the bible the model sometimes reproduced Dickens' English wording
  instead of translating the Japanese text. Translating back into the original language mostly
  reconstructs the original.

## Known limitations

- Personas describe the character as of the end of the work, so later traits can leak into earlier
  chapters (e.g. language proficiency). Episodes are already time-sliced; personas are not yet.
- Builds are not signed or notarized (see below for first launch).
- Depending on the instructions, a provider's safeguards may decline a request.
- The app has been launch-tested on Apple silicon; the Intel Mac and Windows builds pass the engine smoke
  test in CI.

## Upgrading from v3

- v3 translation and evaluation scripts moved to `divergence_z/old/`.
- `--thinking N` / `--budget N` are replaced by `--effort low…max` (old flags still accepted).
- Scripts are importable as a library (`divergence_z.core`, `extract_persona`, `translate_chapter`, …).
- Please read [EthicalRestrictions.md](https://github.com/miosync-masa/divergence-z/blob/main/EthicalRestrictions.md) before use.

### 日本語の要約

v4 は、原作から「人物表・ペルソナ・エピソード」という人物資料を作り、それを使って翻訳とキャラクターの声を作る仕組みに作り直したものです。行ごとに Z軸状態を推定して IAP / ZAP で採点していた v3 は、指標がヒューリスティックで検証できないため `old/` に退避しました。名前の出てこない人物への対応（人物表）、原文と照合した引用、場面単位で計画して訳す章翻訳、キャラクターとの AI チャット、API キーを自分で持ち込んで手元で動くデスクトップアプリ（macOS / Windows）を含みます。モデルが知らない作品（STARGAZER）では、過去の章の伏線や人物の話し方が訳に反映される例が見られ、モデルがよく知る作品（クリスマス・カロル）では差は小さい、という結果でした（少数の質的な比較です）。
